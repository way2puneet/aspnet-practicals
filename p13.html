Implement authentication and authorization

A login page with Forms Authentication, and an Admin folder only the admin can open.

Book: Program 5.7 and Section 5.10Needs CollegeDB database
AimAllow only signed-in users to open the site (authentication), and allow only the user "admin" to open the Admin folder (authorization).
What you learnCodeHow it worksTry itCommon mistakesViva

What you will learn

  • The difference between authentication (who are you?) and authorization (what may you open?).
  • Setting up Forms Authentication in Web.config.
  • Signing in with FormsAuthentication.RedirectFromLoginPage() and out with SignOut().
  • Writing <allow> and <deny> rules, with ? and *.
  • Why passwords are stored as a salted hash, never as plain text.

The idea in simple words

AuthenticationAuthorization
QuestionWho are you?What are you allowed to open?
Done byThe login page checks user name and passwordRules in Web.config
ResultA ticket (cookie) with your user nameThe page opens, or you are sent to the login page

How it flows: you ask for Dashboard.aspx → you have no ticket, so ASP.NET sends you to Login.aspx → you sign in → ASP.NET gives you a ticket and sends you back to the Dashboard. On every later request, the browser sends the ticket, and User.Identity.Name tells the page who you are.

using System;using System.Security.Cryptography; namespace StudentPortal{    public static class PasswordHelper    {        private const int SaltSize = 16;       // bytes        private const int HashSize = 32;       // bytes        private const int Iterations = 10000;         public static string CreateSalt()        {            byte[] salt = new byte[SaltSize];            using (RNGCryptoServiceProvider rng = new RNGCryptoServiceProvider())            {                rng.GetBytes(salt);            }            return Convert.ToBase64String(salt);        }         public static string HashPassword(string password, string salt)        {            byte[] saltBytes = Convert.FromBase64String(salt);            using (Rfc2898DeriveBytes pbkdf2 = new Rfc2898DeriveBytes(password, saltBytes, Iterations))            {                return Convert.ToBase64String(pbkdf2.GetBytes(HashSize));            }        }         public static bool VerifyPassword(string password, string salt, string storedHash)        {            byte[] computed = Convert.FromBase64String(HashPassword(password, salt));            byte[] stored = Convert.FromBase64String(storedHash);             if (computed.Length != stored.Length)            {                return false;            }             int difference = 0;            for (int i = 0; i < computed.Length; i++)            {                difference |= computed[i] ^ stored[i];            }            return difference == 0;        }    }}

How it works

  1. <authentication mode="Forms"> <forms loginUrl="~/Login.aspx" defaultUrl="~/Dashboard.aspx" timeout="20" ... />Switches on Forms Authentication. loginUrl is where users without a ticket are sent. timeout logs the user out after 20 idle minutes.
  2. <authorization> <deny users="?" /> </authorization>? means anonymous (not signed in) users. They cannot open any page, except the login page itself.
  3. <location path="Admin"> ... <allow users="admin" /> <deny users="*" />For the Admin folder only: allow "admin", deny everyone else (* means all users). Rules are checked from top to bottom and the first match wins.
  4. string sql = "SELECT PasswordSalt, PasswordHash FROM AppUser WHERE UserName = @UserName";The login page looks up the user. The table stores a salted hash, not the password itself.
  5. PasswordHelper.VerifyPassword(txtPassword.Text, salt, storedHash)Hashes the typed password with the same salt and compares the result with the stored hash. If they match, the password is right.
  6. FormsAuthentication.RedirectFromLoginPage(userName, chkRemember.Checked);Creates the ticket, stores it in a cookie, and sends the user to the page they first asked for (ReturnUrl), or to the Dashboard. The second value decides whether the cookie survives closing the browser.
  7. lblWelcome.Text = "Welcome, " + HttpUtility.HtmlEncode(User.Identity.Name) + ...;On any page after login, User.Identity.Name gives the signed-in user name.
  8. lnkReports.Visible = (User.Identity.Name == "admin");Shows the Reports link only to admin. This is only for convenience; the real protection is the rule in Web.config.
  9. FormsAuthentication.SignOut(); FormsAuthentication.RedirectToLoginPage();Logout: removes the ticket and goes back to the login page.

Common mistakes

  • Putting <deny users="*" /> before <allow users="admin" />. The first matching rule wins, so even admin is denied.
  • Forgetting <deny users="?" />. The default rule allows everyone, so pages open without login.
  • Storing passwords as plain text in the table. Anyone who sees the database would see every password.
  • Hiding a link and thinking the page is protected. A user can still type the address. Protection must come from the Web.config rules.
  • Not running AppUser.sql, which gives "Invalid object name 'AppUser'".

Viva questions

Difference between authentication and authorization?
Authentication checks who the user is (login). Authorization decides which pages that user may open (rules in Web.config). Authentication comes first.
What are the types of authentication in ASP.NET?
Windows authentication, Forms authentication, and (in newer applications) token-based external logins. Forms authentication is used for public websites with a login page.
What do ? and * mean in authorization rules?
? means anonymous (not signed in) users. * means all users.
What does RedirectFromLoginPage() do?
It creates the authentication ticket, stores it in a cookie, and redirects the user to the page in ReturnUrl or to the default page.
What is a salt? Why hash passwords?
A salt is a random value stored with each user. The password plus salt is hashed, and only the hash is stored. Even if the table is stolen, the real passwords cannot simply be read.
How do you protect a single folder?
With a <location path="FolderName"> element in the main Web.config, or a separate Web.config inside that folder, containing allow and deny rules.
