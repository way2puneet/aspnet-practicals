What you will learn

  • How to create and run an ASP.NET Web Forms page in Visual Studio.
  • The two files of every page: the design (.aspx) and the C# code (.aspx.cs).
  • What a server control is and why it needs runat="server".
  • What a postback is: the page goes to the server, the C# code runs, and the page comes back.

The idea in simple words

A web application runs on a web server. The browser asks for a page, the server runs your C# code, and sends back plain HTML. The browser never sees your C# code.

When you click the button, the browser sends the form back to the same page on the server. This is called a postback. ASP.NET then runs the method connected to the button, btnShow_Click, which puts the message in the label.

Development tools used: Visual Studio (to write, build and run), IIS Express (the small web server that starts when you press Ctrl + F5), and your browser (to see the result). Steps to create the project are on the Setup page.

How it works

  1. <%@ Page Language="C#" ... CodeBehind="Welcome.aspx.cs" Inherits="StudentPortal.Welcome" %>The @ Page directive is the first line of every page. It says the language is C# and links this design file to the class Welcome in the code file.
  2. <form id="form1" runat="server">Every page has one server form. All controls must be inside it, otherwise they cannot send data back to the server.
  3. <asp:TextBox ID="txtName" runat="server" MaxLength="40"></asp:TextBox>A server control. runat="server" lets C# use it by its ID, txtName. MaxLength stops the user typing more than 40 characters.
  4. <asp:Button ID="btnShow" ... OnClick="btnShow_Click" />OnClick names the C# method that runs on the server when the button is clicked.
  5. string name = txtName.Text.Trim();Reads what the user typed. Trim() removes extra spaces at the start and end.
  6. if (name == "") { ... "Please enter your name." }If nothing was typed, the label turns red and asks for a name.
  7. lblMessage.Text = "Welcome, " + Server.HtmlEncode(name) + "! ...";Otherwise the label shows the message in green. Server.HtmlEncode() makes sure that whatever the user types is shown as plain text and not run as HTML.

Common mistakes

  • Pasting the .aspx code in Design view instead of Source view. Always switch to Source first.
  • Giving the Web Form a different name (for example WebForm1). The class name must match Inherits="StudentPortal.Welcome".
  • Forgetting runat="server". Without it, C# cannot find the control and you get "The name ... does not exist in the current context".
  • Writing OnClick="btnShow_Click" in the page but naming the method differently in C#. The two names must be the same.

Viva questions

What is ASP.NET?
ASP.NET is a server-side framework from Microsoft, part of the .NET Framework, for building dynamic web pages and web applications.
What is a postback?
Sending the page back to the same page on the server, along with the values typed by the user. It happens when you click a button. The server runs the event handler and returns the updated page.
What are the two main files of a Web Form?
The .aspx file holds the design (HTML and server controls). The .aspx.cs file, called the code-behind file, holds the C# code.
Why is runat="server" needed?
It tells ASP.NET to create the control as an object on the server, so the C# code can read and change it using its ID.
What is IIS Express?
A small web server that comes with Visual Studio. It runs your pages on your own computer at an address such as https://localhost:44312/.
Why is Server.HtmlEncode() used?
It converts characters such as < and > into safe text, so anything the user types is shown as text and is never run as HTML or script.
