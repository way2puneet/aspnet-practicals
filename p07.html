Develop a web application using data controls

Choose a course and a GridView lists its students. No C# code at all.

Book: Program 4.5Needs CollegeDB database
AimShow the students of a selected course in a GridView, using a SqlDataSource data control and no C# code.
What you learnCodeHow it worksTry itCommon mistakesViva

What you will learn

  • What data controls are: data source controls (like SqlDataSource) and data-bound controls (like GridView).
  • Reading the connection string from Web.config with <%$ ConnectionStrings:CollegeDB %>.
  • Passing a value from another control into the SQL query with a ControlParameter.
  • Connecting a GridView to a data source with DataSourceID.

The idea in simple words

There are two kinds of data controls, and they work as a pair:

  • A data source control (SqlDataSource) talks to the database. It is not shown on the page.
  • A data-bound control (GridView) shows the data on the page.

You connect them with one property: DataSourceID="sdsStudents". The SqlDataSource runs the SELECT query, and the GridView draws one row for each record. ASP.NET does all of this by itself, so the code-behind file is empty.

The query has a parameter, @Course. Its value comes from the drop-down list, through a ControlParameter. When the course changes, the grid shows the new students automatically.

Before you run: create the CollegeDB database and add the connection string to Web.config, as shown in Setup.

Add a Web Form named CourseStudents.

How it works

  1. <asp:DropDownList ID="ddlCourse" runat="server" AutoPostBack="True">Changing the course posts the page back at once.
  2. ConnectionString="<%$ ConnectionStrings:CollegeDB %>"Reads the connection string named CollegeDB from Web.config. The database details are written only once, in Web.config.
  3. SelectCommand="SELECT RollNo, StudentName, Semester, City, Marks FROM Student WHERE Course = @Course ORDER BY RollNo"The query the data source runs. @Course is a parameter: a placeholder filled in safely just before the query runs.
  4. <asp:ControlParameter Name="Course" ControlID="ddlCourse" PropertyName="SelectedValue" Type="String" />Fills @Course with the SelectedValue of the drop-down list.
  5. <asp:GridView ID="gvStudents" runat="server" DataSourceID="sdsStudents" ... EmptyDataText="No students found.">The GridView gets its rows from sdsStudents. Its columns are created automatically from the field names. If there are no rows, it shows EmptyDataText.

Common mistakes

  • Misspelling the connection string name. CollegeDB in the page must match name="CollegeDB" in Web.config exactly.
  • Writing <%= %> or <%# %> instead of <%$ %>. Only the $ form reads from Web.config.
  • Forgetting AutoPostBack="True", so the grid does not change until some other button is clicked.
  • The parameter name without @ in Name="Course" must match @Course in the query.

Viva questions

What are data controls?
Controls used to work with data. Data source controls (SqlDataSource, ObjectDataSource, XmlDataSource) connect to the data, and data-bound controls (GridView, DetailsView, FormView, Repeater, DataList, ListView) display it.
What is SqlDataSource?
A data source control that connects to a SQL Server database and runs SELECT, INSERT, UPDATE and DELETE commands without C# code.
What does DataSourceID do?
It connects a data-bound control to a data source control by giving the ID of the data source. The control then binds itself.
What is a ControlParameter?
A parameter whose value is taken from a property of another control on the page, such as the SelectedValue of a DropDownList.
Why is the connection string stored in Web.config?
It is written once and used by every page, it can be changed without recompiling, and ASP.NET never sends Web.config to browsers.
