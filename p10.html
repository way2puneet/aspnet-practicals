Develop a database application to perform insert, update and delete operations

One form to add, find, change and remove student records with ADO.NET commands.

Book: New program (combines Programs 4.1, 4.4 and 5.1)Needs CollegeDB database
AimBuild a form that inserts, updates and deletes records in the Student table using SqlConnection, SqlCommand and ExecuteNonQuery().
What you learnCodeHow it worksTry itCommon mistakesViva

What you will learn

  • The ADO.NET objects: SqlConnection, SqlCommand, SqlDataReader.
  • Running INSERT, UPDATE and DELETE with ExecuteNonQuery(), which returns the number of rows changed.
  • Using parameters (@RollNo, @Name...) instead of joining text into SQL.
  • Catching a duplicate roll number with SqlException.

The idea in simple words

Each button runs one SQL statement on the database:

ButtonSQLADO.NET method
InsertINSERT INTO Student ... VALUES (...)ExecuteNonQuery()
UpdateUPDATE Student SET ... WHERE RollNo = @RollNoExecuteNonQuery()
DeleteDELETE FROM Student WHERE RollNo = @RollNoExecuteNonQuery()
FindSELECT ... WHERE RollNo = @RollNoExecuteReader()

The steps are always the same: open a connection, create a command with parameters, execute it, close the connection. The using block closes the connection for you, even if an error happens.

To update or delete: type a roll number, click Find to load the record, change it, then click Update or Delete. The grid below always shows the current table.

Before you run: create the CollegeDB database as shown in Setup.

How it works

  1. using (SqlConnection con = new SqlConnection(cs)) using (SqlCommand cmd = new SqlCommand(sql, con))Creates the connection and the command. When the using block ends, the connection is closed automatically.
  2. cmd.Parameters.AddWithValue("@RollNo", txtRollNo.Text.Trim().ToUpper());Gives a value to the @RollNo placeholder in the SQL. ToUpper() makes bca101 and BCA101 the same.
  3. con.Open(); return cmd.ExecuteNonQuery();ExecuteNonQuery() runs a statement that changes data and returns how many rows were changed. All three operations share this one Execute() method.
  4. catch (SqlException ex) { if (ex.Number == 2627 || ex.Number == 2601) ... }RollNo is UNIQUE in the table. Inserting the same roll number again makes SQL Server raise error 2627 or 2601, which is shown as a friendly message.
  5. int rows = Execute("UPDATE Student SET ... WHERE RollNo = @RollNo", true); if (rows == 1) ...If no record has that roll number, 0 rows change. Checking the return value tells the user whether the update really happened.
  6. <asp:Button ID="btnDelete" ... CausesValidation="false" OnClientClick="return confirm('Delete this record?');" />Delete needs only the roll number, so it skips the validators. OnClientClick asks for confirmation in the browser first; Cancel stops the postback.
  7. if (reader.Read()) { txtName.Text = reader["StudentName"].ToString(); ... }Find uses a SqlDataReader. Read() returns true if a matching row exists, and its values are copied into the form.
  8. BindGrid();Called after every change, so the grid shows the table as it is now.

Common mistakes

  • Forgetting con.Open(). The command then fails with "ExecuteNonQuery requires an open and available Connection".
  • Joining user text into SQL, like "WHERE RollNo = '" + txtRollNo.Text + "'". Use parameters to prevent SQL injection.
  • An UPDATE or DELETE without a WHERE clause. It changes or removes every row in the table.
  • Forgetting using System.Data.SqlClient; at the top, so SqlConnection is not recognised.

Viva questions

What is ADO.NET?
The set of .NET classes used to connect to databases, run commands, and read and update data.
What does ExecuteNonQuery() return?
The number of rows affected by an INSERT, UPDATE or DELETE statement (and -1 for statements such as CREATE TABLE).
Difference between ExecuteNonQuery, ExecuteScalar and ExecuteReader?
ExecuteNonQuery changes data and returns the row count. ExecuteScalar returns a single value, such as COUNT(*). ExecuteReader returns a SqlDataReader for reading rows.
What is SQL injection and how do parameters prevent it?
SQL injection is when typed input changes the meaning of an SQL statement. With parameters, the input is always treated as a value, never as part of the SQL command.
Why is the using statement used with SqlConnection?
It closes and releases the connection automatically when the block ends, even if an exception occurs.
